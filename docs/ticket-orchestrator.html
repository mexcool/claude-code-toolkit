Ticket orchestrator

One ticket, one worktree, one herdr tab. A Claude lead passes files between a Claude implementer and Codex reviewers, sorts what the reviewers find, and comes back to you only for the steps that need a person.

How a run starts
$ claude --worktree -n proj-123-lead
> orchestrate PROJ-123

Needs herdr. Workers launch with ORCH_CLAUDE_CMD and ORCH_CODEX_CMD, or with stock claude and codex with permissions bypassed.

      One review round

      The kickoff and the PR go through the same round. The lead sits in the middle, so every finding passes its sort before the implementer sees it.

      must-fixrelayed

      Wrong behaviour, a ticket requirement not met, or a security problem.

      should-fixrelayed if small

      Real and small, and inside the contract the kickoff agreed.

      droplogged

      Nits, style, “you could also”, edge cases that cannot happen, new abstractions, extra docs, speculative tests. A test that checks a contract item or measures an accepted risk is not speculative.

      The lead never drops a finding only because it contradicts the ticket, the contract or an earlier decision. It needs evidence to drop one, and a product question goes to you.

      Why nobody watches the panes

      Every handoff is a file

      Each message from the lead names the file to write. The worker also prints it word for word in its chat, so you can read along in the apps, or catch up later from log.md.

      Workers talk only to the lead

      No worker messages another. Every finding goes through the lead's sort before it reaches the implementer, which is what keeps scope from growing each round.

      herdr wakes the lead

      The lead sends with herdr agent prompt <worker> "…" --wait in the background and ends its turn. The call returns when the worker's turn ends. The lead then looks for the file, since herdr reads agent state from the screen. No file yet means a two-minute grace window, then a look at the pane.

      No dialogs in any pane

      A pane with an open dialog cannot take a prompt, so the loop would stall until you came back. Workers write their questions into their files instead.
